# 架构方案：RePSS 训练测评平台

版本：v0.2（待用户确认）

相对 v0.1 的变更：v0.1 描述的是整条研究主线（数据、单模态、融合）。本次只交付其中的训练与测评平台。融合、VIPL-HR、困难子集分析仍按研究计划后置，不进入本轮实现。目录约定保持不变：实验导入平台，平台导入 `baselines/`，不改上游模型源码。

## 需求概述

在已经克隆的基础模型之上，做一个配置驱动的训练测评平台。之后每次实验只在 `experiments/expNNN_*/` 里追加算法（包装网络、替换损失），用同一条命令训练或评测。

- 输入：一份实验配置。配置指定基线名称、来源（工具箱或作者原版）、数据、随机种子，以及可选的实验插件。数据可以是合成片段，或将来指向本地数据集目录。
- 输出：预测波形、片段级心率（bpm）、指标表（MAE、RMSE、MAPE、Pearson、SNR）、本次实际生效的配置副本。
- 约束：
  - 技术栈沿用 Python 与 PyTorch，与现有仓库一致。
  - 单卡约 8 GB 显存应能跑通短片段冒烟训练。
  - 受试者划分由平台生成并落盘；同一配置与种子可重跑。
  - 不修改 `baselines/` 内的上游文件。研究改动只出现在实验目录的插件里。
  - 本机尚无 `data/` 人脸视频。本轮验收使用合成片段。真实数据路径缺失时，命令应明确失败，而不是进入模型内部报错。
- 已下拉、必须登记的基线：
  - 无监督，只评测：GREEN、ICA、CHROM、POS。Python 实现来自 `baselines/rPPG-Toolbox/unsupervised_methods/`。`iphys-toolbox` 是 MATLAB 对照，平台不调用 MATLAB。
  - 监督，工具箱：DeepPhys、TS-CAN、EfficientPhys、PhysNet、PhysFormer、PhysMamba、RhythmFormer。
  - 监督，作者原版：PhysNet、PhysFormer、RhythmMamba。与工具箱同名模型用配置里的来源字段区分，不另起一套指标。
- 非目标：实时部署、血压、自监督预训练、雷达、RGB–NIR 融合实现、下载或爬取人脸数据。

## 可行性结论

可行。

- 技术成熟度：工具箱已经把训练、评测和无监督推理分成可调用入口；作者原版网络都能前向输出波形。缺的是统一样本、统一指标和实验插件位，不是新的估计方法。
- 数据可得性：本轮不依赖 PURE、UBFC-rPPG。合成片段足够验证注册、训练一步、插件替换和指标表。真实数据接口先留空实现，数据到位后只补读取器。
- 资源：无监督与 PhysNet 短片段不需要额外编译扩展。RhythmMamba 依赖需单独编译的算子，登记进平台，但缺少依赖时只标记为不可用，不挡住其他模型。

## 模块划分

| 模块 | 职责 | 所需算法/逻辑/架构类型 |
|------|------|------------------------|
| 统一样本 | 把一段视频、可选波形、采样率、受试者编号收成一种记录 | 数据传输对象；全平台只此一种样本 |
| 基线注册表 | 按名称和来源找到适配器，并报告该模型当前能否导入 | 注册表；导入失败时标记不可用 |
| 基线适配器 | 把统一样本变成该模型需要的张量布局，调用上游前向，收回一条波形 | 适配器。布局转换留在适配器内，实验代码看不到模型私有输入 |
| 合成与真实数据 | 生成固定长度片段，或在数据目录存在时读取；按受试者做确定性划分 | 确定性伪随机合成；受试者分组划分 |
| 训练循环 | 只服务监督模型：取批次、算损失、更新参数、保存检查点 | 配置驱动的小批量训练。默认损失为时域相关类；实验可替换 |
| 心率解码 | 由波形得到 bpm | 带通滤波加功率谱主峰。带通上下限来自配置 |
| 指标 | 汇总片段级误差 | 确定性统计，无训练 |
| 插件加载 | 从实验目录导入可选模块，包装模型或替换损失 | 策略注入。插件缺省时行为与原基线一致 |
| 命令入口 | `train` 与 `eval` 两条子命令，读同一份配置 | 配置驱动流水线 |

平台代码放在仓库根的 `platform/`，不放进某一次实验，也不放进 `baselines/`。依赖方向只有一条：`experiments` → `platform` → `baselines`。

```text
platform/
  repss_platform/          注册表、适配器、训练、评测、插件加载
  configs/models.yaml      已登记基线的名称、种类、默认来源、是否需要编译扩展
experiments/
  _template/               复制后填写配置；插件文件可留空
  expNNN_短名/
    config.yaml
    plugin.py              可选。新算法只写在这里
    outputs/               日志与表格，不进版本库
```

## 数据流与接口约定

```text
实验 config.yaml
    → 注册表解析基线适配器
    → 若配置写了插件，则包装模型或替换损失
    → 统一样本 {video[T,H,W,3], wave[T] 或空, fs, subject_id}
    → 适配器前向
    → 预测波形 [T]
    → 心率标量
    → outputs/metrics.csv 与 metrics.json
```

约定：

- 统一样本的视频是 float32，数值范围 \[0, 1\]，通道在最后一维，长度 T 与空间尺寸由配置给出。第一版监督冒烟使用 T=128、边长 128；无监督冒烟使用更短的 T，仍由配置给出。适配器负责改成上游要的布局，例如通道在前、帧差分双分支，或作者网络额外的前向参数。
- 波形与帧数等长。无监督方法没有训练标签时，评测仍要求样本带波形，否则只输出预测、不计算误差，并在日志标明缺标签。
- 监督模型默认损失是时域相关类。插件若提供损失，训练循环调用插件，不再调用默认损失。
- 插件只能做两件事：`wrap_model(model) -> model`，返回值仍须输出波形；`loss_fn(pred, target) -> 标量`。不提供则跳过。插件不得写入 `baselines/`。
- 划分文件是受试者 ID 列表，由种子决定。合成数据的受试者编号在生成时写死，保证同一配置两次运行得到同一划分。
- 一次运行结束必须留下：`metrics.csv`、`metrics.json`、实际生效的配置副本。检查点只在 `train` 时写出。
- 未知基线名称、来源与名称不匹配、插件导入失败、数据路径不存在，都在进入前向之前退出，并在报错里写明配置项名称。

## 开发步骤与验收标准

| 步骤 | 描述 | 所需算法类型 | 验收标准（可测试） |
|------|------|--------------|---------------------|
| 1 | 注册表与能力探测 | 注册表 | 列出本节登记的全部名称。查询不存在的名称时失败并包含该名称。RhythmMamba 在编译扩展缺失时标记不可用，其余不依赖该扩展的模型仍可查询 |
| 2 | 心率解码与五项指标 | 带通与功率谱主峰；确定性统计 | 30 秒、采样率已知的合成正弦加弱噪声，估计心率与真实频率对应的 bpm 相差不超过 1。对一组已知的预测/标签心率，MAE、RMSE、MAPE、Pearson、SNR 与手算一致到小数点后 4 位 |
| 3 | 无监督适配器，只评测 | 色度投影类无监督 rPPG | GREEN、ICA、CHROM、POS 各对一段合成片段跑通，输出长度等于 T 的有限数值波形，以及一份含五项指标的表。不产生检查点 |
| 4 | 监督训练循环与 PhysNet 适配器 | 时空序列回归；时域相关类损失；小批量训练 | 工具箱 PhysNet 在合成片段上训练 1 个批次：损失为有限数，检查点可重新加载，评测写出五项指标。随机输入形状与配置中的 T、边长一致 |
| 5 | 其余监督适配器的登记与前向 | 适配器 | DeepPhys、TS-CAN、EfficientPhys、PhysFormer、PhysMamba、RhythmFormer，以及作者原版 PhysNet、PhysFormer，各用 1 个合成批次做一次前向，输出波形长度与 T 一致。RhythmMamba 仅在依赖可用时做同样的前向；不可用时步骤 1 的标记仍成立，本步跳过并记录原因 |
| 6 | 实验插件 | 策略注入 | 实验目录提供一个把损失替换成常数标量的插件。训练日志中的损失等于该常数，且 `baselines/` 无文件改动。不提供插件时，损失回落到时域相关类 |
| 7 | 实验模板与失败路径 | 配置驱动流水线 | 从 `_template` 复制的配置能调用平台的 `train` 或 `eval`。数据路径指向不存在目录时，退出信息包含该路径，且不出现模型前向的报错 |

步骤 4 是本轮唯一的真实反传冒烟，选定工具箱 PhysNet，因为它是波形回归、不依赖额外编译扩展，显存占用适合短片段。步骤 5 只验证适配器把样本送进上游并拿回波形，不在本轮把每个大模型都训练到收敛。

## 风险与外部依赖

- 各模型输入不一致：PhysNet 一类要通道在前的片段；DeepPhys、TS-CAN 一类要外观帧与帧差分两路；PhysFormer 前向还有额外参数。这些差异若漏到实验配置里，以后每加一个算法都要改样本格式。验收时用步骤 5 的前向卡住这件事。
- RhythmMamba 的选择扫描与因果卷积扩展可能编译失败。平台把它列为可缺席依赖，不用它的失败去阻断 POS 或 PhysNet。
- 作者原版与工具箱版本不是同一份代码。配置必须写来源；来源省略时用 `platform/configs/models.yaml` 里的默认来源，并写进配置副本。
- 本机没有人脸数据集。本轮不报告 PURE 或 UBFC 上的 MAE。真实数据读取器留接口，等数据放到 `data/` 后再接，不在本轮下载视频。
- 面部视频是生物特征。平台不包含爬取脚本，不把数据路径下的视频复制进版本库。
